PEEC — исправленная версия
==========================

Полный проект с исходниками, сетками, примерами и регрессионными тестами.
Исправлены причины девяти FAIL из исходного набора. Допуски исходных тестов
не изменены. Добавлено шесть проверок новых численных и программных путей.

Запуск
------

Распаковать в новую папку. Все команды выполнять из каталога PEEC.
Нужны GCC с OpenMP, GNU Make и Python 3. Проверено на Linux; Windows-сборка
в этой среде не выполнялась.

```sh
make test
make -f Makefile.tests verify-asan
make -f Makefile.tests verify-spice
make -j4
./PeecSolver --config cases/run_scattering.cfg
```

`make test` действительно запускает тесты; `make run-test` делает то же самое.
Быстрая проверка только ядра: `make -f Makefile.tests verify-core`.
Полный основной набор включает сборку и несколько расчётов пластины.
Для `verify-spice` нужны NumPy и SciPy: `python3 -m pip install numpy scipy`.
ASan/UBSan должны поддерживаться компилятором. Проверка ASan посвящена времени
жизни строк конфигурации; обнаружение утечек в этом отдельном пробнике отключено.

Файл конфигурации теперь можно явно выбрать через `--config FILE` на любой ОС.
Аргументы командной строки учитываются и на Windows. Старый запуск без аргументов
на Windows по-прежнему читает cases/run_lightning.cfg. Пути внутри конфигурации
отсчитываются от текущего рабочего каталога; запускать из PEEC.
`--config FILE` используется отдельно, без дополнительных CLI-переопределений.

Что исправлено
--------------

- Квадратура 1/R: внутренний интеграл по треугольнику вычисляется аналитически
  через реберные интегралы и телесный угол. Для совпадающих треугольников весь
  двойной интеграл аналитический; для близких и соприкасающихся — адаптивная
  внешняя квадратура с делением длиннейшего ребра. Сохраняется взаимность.
  При исчерпании глубины адаптации возвращается ошибка, а не произвольное число.
  Близость оценивается консервативно по ограничивающим параллелепипедам.
- Комплексный LU: введено масштабирование строк и столбцов перед выбором pivot.
  Правая часть и решение преобразуются согласованно. Проверка невязки остаётся
  на исходной физической матрице. Допуск pivot не ослаблен; действительно
  вырожденная система по-прежнему отклоняется.
- Неверная геометрия aperture-map завершает построение с ошибкой и очищает
  частично созданную структуру вместо продолжения расчёта с неверными токами.
- Неподдерживаемые порядки RCS отклоняются в CLI и численном API. Ошибка интеграла
  внутри OpenMP передаётся вызывающему коду. Порядки: 2, 3, 4, 5, 6, 8, 10, 12, 16.
- Длинные названия параметров из cases/*.cfg принимаются как синонимы коротких.
  Проверяется корректность диапазона углов и шага развёртки RCS.
- Конфигурация владеет копиями строк. Освобождение временного argv больше не
  инвалидирует пути. В главном драйвере вызывается config_free() на выходах.
  При использовании C API: config_set_defaults(), config_parse_cli(), config_free().
  Владеющую конфигурацию нельзя освобождать через её поверхностную копию.
- `make run-rcs` больше не передаёт неподдерживаемый `--task` отдельному main_rcs.c.
- SPICE: знаки ёмкостей сохраняются при представлении C = inv(P). Отрицательные
  ветви не выбрасываются. Проверяется положительная определённость полной
  ёмкостной матрицы, включая результат после отсечения малых ветвей.
  `run` находится перед `wrdata`; ток шунта вычисляется как V/R, ток источника
  измеряется через последовательный нулевой источник напряжения. Начальные
  условия transient — нулевые (`uic`).
- В примере RCS уменьшено ka с 1 до 0.02: при длине тела 7 м и a=1 прежнее kD=7
  выходило далеко за область квазистатики. Развёртка при фиксированном падающем
  направлении названа бистатической.

Точность и ограничения
---------------------

Локальные тесты прямоугольников 1:1, 10:1 и 100:1 требуют ошибку не более 0,1%.
Это критерий квадратуры, а не гарантия такой же точности тока или ЭПР.
Адаптивное интегрирование близких панелей дороже прежнего фиксированного правила;
для больших моделей сборка может заметно замедлиться. LU остаётся плотным.

Это квазистатический решатель. Полноволновой retarded-режим не подключён.
Для физических результатов нужны проверка применимости модели и сходимости
по сетке и шагу времени. Результаты тестов не заменяют сравнение с независимым
электромагнитным решателем или измерениями.

В cases/run_lightning_slot_cells.cfg ширина, толщина стенки и параметры щели
остаются исходными шаблонными данными; их нужно согласовать с реальной геометрией.
Исправления программных ошибок не подтверждают физическую корректность этого
эквивалента щели.

SPICE-экспорт использует алгебраические ветви со знаком. Пассивность определяется
полной матрицей, отдельная отрицательная ёмкость не является физической деталью.
Нулевые cap-cutoff и k-cutoff сохраняют матричные связи; ненулевые дают приближение.
Параметр r-floor отдельно добавляет малое сопротивление к идеальным PEC-ветвям.
Тест проверяет восстановление C и порядок команд, но не запускает ngspice.
Сам симулятор в среде проверки отсутствовал; согласование transient-кривых
C-решателя и ngspice остаётся отдельной проверкой.

Состав архива
-------------

Старые матричные кэши, результаты расчётов, объектные и исполняемые файлы исключены.
Они пересоздаются из исправленных исходников; старые L/P использовать не следует.
Исторические альтернативные файлы mainTESTS.c, main_auto_os.c и
aperture_couplingDO.c сохранены, но не входят в COMMON_SOURCES и не проверялись
как самостоятельные программы. Рабочие точки входа — main.c и main_rcs.c.

Свежие протоколы: tests/reports/. Исторический результат 8 PASS / 9 FAIL:
tests/BASELINE_RU.md. Команды и критерии каждого теста: tests/README_RU.md.

Математическая ссылка для аналитического потенциала равномерного треугольника:
[van Oosterom, 2011](https://pmc.ncbi.nlm.nih.gov/articles/PMC3249024/).
Команды SPICE сверялись с [руководством ngspice](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf).
