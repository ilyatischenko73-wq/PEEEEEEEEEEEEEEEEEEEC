# PEEC на Fortran 2008

Самостоятельный CPU-решатель на Fortran, перенесённый с C-версии из этого
репозитория (исходный коммит: e73119f72f8c342133c9080e780feafc5424e5a2).
Исполняемый файл Fortran не компилирует и не вызывает исходное ядро на C.
Для плотной линейной алгебры используется LAPACK; сборка L/P распараллелена OpenMP.

## Графический интерфейс

[PEEC Studio: установка и руководство](../gui/README_RU.md) — выбор задачи и сетки,
параметры возбуждения и шунта, выбор узлов мышью, запуск Fortran,
просмотр VTK и графики ЭПР/молнии/шунта на русском языке.

## Сборка и запуск

Команды выполняются **из корня репозитория**, где находятся папки cases и meshes.
**Windows / Visual Studio / Intel ifx:** [пошаговая инструкция](WINDOWS_RU.md).
При запуске без аргументов открывается меню задач. Выбор также задаётся
константой selected_task в fortran/app/main.f90.

Для Debian/Ubuntu:

```sh
sudo apt-get install gfortran liblapack-dev libblas-dev make
make -f Makefile.fortran
./build/fortran/PeecSolverFortran --config cases/run_scattering.cfg
```

Другие существующие конфигурации запускаются тем же способом:

```sh
./build/fortran/PeecSolverFortran --config cases/run_rcs.cfg
./build/fortran/PeecSolverFortran --config cases/run_lightning.cfg
./build/fortran/PeecSolverFortran --config cases/run_lightning_slot_cells.cfg
```

Быстрый запуск на небольшой сетке:

```sh
./build/fortran/PeecSolverFortran --task scattering \
  --mesh meshes/plate.msh --frequency 1e6 --parallel 2 \
  --save-matrices --matrix-dir results/FORTRAN/matrices \
  --vtk --vtk-dir results/FORTRAN
```

Поддерживаются длинные и короткие имена параметров исходного CLI.
`--config FILE` применяется отдельно от остальных параметров.
Файл конфигурации допускает комментарии # и пути в одинарных/двойных кавычках.
Пути в конфигурациях отсчитываются от рабочего каталога.

## Что перенесено

| Режим / данные | Реализация |
|---|---|
| Сетка | ASCII Gmsh 4.1, четырёхузловые четырёхугольники; порядок узлов из файла |
| Топология | Ориентация ребра по первому вхождению, как в C; двойственные области |
| L, P, A, PAT, R | Те же области интегрирования, квадратуры и PEC-модель |
| Квадратура 1/R | Аналитический внутренний интеграл по треугольнику; аналитический self; адаптация близких пар |
| Рассеяние | Комплексная система PEEC, точный sinc-интеграл плоской волны по ребру |
| ЭПР / RCS | Бистатическая развёртка; интегрирование двойственных областей или midpoint |
| Молния | Двойная экспонента и плоский падающий импульс |
| Переходный расчёт | Неявный Эйлер и правило трапеций; нулевые начальные условия |
| Два этапа | Закрытая модель → токи через aperture-map → открытая модель, опциональный шунт |
| Slot-cells | Распределённые LC-ячейки и опциональный резистивный шунт |
| Результаты | Matrix Market, Legacy VTK, файлы шунта/щели и дополнительные временные CSV |

**Все внешние индексы остаются с нуля**, включая `--strike-node`,
`--return-node`, `--shunt-a-node`, `--shunt-b-node`,
aperture-map JSON и slot_cells.dat. Внутри Fortran индексы преобразуются к 1-based.
Ориентация и порядок рёбер сохранены для совместимости существующих aperture-map.

В переходном режиме неизвестная Vc — собственное узловое напряжение:
F(j)=1/P(j,j), Q=F*Vc, phi=P*Q. Гармоническая неизвестная phi — полный потенциал.
Различие сохранено в уравнениях, восстановлении заряда и VTK-экспорте.

## Проверки

```sh
make -f Makefile.fortran test
make -f Makefile.fortran compare
make -f Makefile.fortran debug
```

- test: аналитические интегралы прямоугольников 1:1, 10:1, 100:1;
  взаимность, масштабирование и близкие панели; LU, вырожденность;
  аналитическое решение гармонического контура; порядок сходимости Эйлера/трапеций,
  энергия, заряд, закон Ома, LC-ячейки и геометрия aperture-map.
- Затем выполняются небольшие расчёты всех шести сочетаний режимов/возбуждения
  и проверки отклонения неверных входных данных.
- compare: собирает исходный C-решатель и сравнивает матрицы, VTK-поля и ЭПР
  на синтетической сетке, переходные процессы closed/two-stage/slot-cells,
  падающий импульс и рассеяние на исходной meshes/plate.msh.
  Относительные допуски: 2e-11 для матриц и 2e-7 для полей/ЭПР.
- debug: повторяет численные и CLI-проверки с `-fcheck=all`.

Python 3 нужен только для тестового скрипта и существующих вспомогательных программ.
Скрипт сравнения использует стандартную библиотеку Python.
Протоколы сохраняются в build/fortran-tests. Автоматический запуск:
.github/workflows/fortran.yml. Результат запуска следует смотреть в GitHub Actions;
наличие теста само по себе не означает, что он прошёл.

## Выходные файлы

Имена VTK и полей соответствуют исходному решателю:
scattering_surface.vtk, scattering_edges.vtk, rcs_solution_surface.vtk,
lightning_closed_surface_000000.vtk, lightning_stage1_*, lightning_stage2_*,
lightning_slot_cells_*. Сохранены phi_V, charge_C, sigma_C_m2, current_A,
комплексные re/im/abs поля и векторы J_A_m.

Матрицы сохраняются под именами L.mtx, P.mtx, A.mtx, PAT.mtx, R.mtx.
Для двух этапов используются подкаталоги stage1 и stage2.
Их можно передать существующему export_peec_spice.py.

Переходные CSV дополнительно записываются в `--vtk-dir` даже без `--vtk`:
время, ток источника (для Stage 2 — половина суммы абсолютных токов через щель),
максимум тока ребра, суммарный заряд, ток шунта и максимум тока LC-ветвей.
В исходной версии эти CSV отсутствуют. Подробный диагностический текст C-драйвера
упрощён; численные поля предназначены для сравнения через экспортированные файлы.

## Границы переноса

- Сохраняется **квазистатическая** модель. Retarded-режим отсутствует и
  отклоняется явно, как неподключённый режим исходного проекта.
- Python-генераторы сеток, визуализация, SPICE-экспорт и GPU-скрипты остаются
  существующими вспомогательными программами на Python. Они не переписаны на Fortran.
- Пустые и исторические альтернативные C-файлы не переносились.
  Рабочие режимы обоих C-драйверов доступны через `--task` одного Fortran-файла.
- Изолированные узлы, повторные теги узлов и некорректные четырёхугольники
  отклоняются до сборки матриц. JSON-парсер принимает документированную схему
  node_mapping/cover_edges; неизвестные ключи и дубликаты считаются ошибкой.
- Реальный LU также масштабирует строки/столбцы перед LAPACK. Это отличается
  от реализации реального LU на C, сохраняя физическую систему уравнений.
- Плотные матрицы требуют O(N²) памяти и O(N³) времени факторизации.
  Большие сетки body_* заметно дороже проверок на пластине.
- Проверки переноса не подтверждают физическую применимость PEEC к любой
  частоте/геометрии. Ограничения исходного README_RU.md и шаблонные параметры
  щели остаются актуальными.
- Windows, GPU-исполнение и ngspice этим набором не проверяются.
  Подготовлена нативная сборка Windows через Intel ifx; инструкция WINDOWS_RU.md.
